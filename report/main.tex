\begin{abstract}
  Sphinx is a packet format widely used in decentralized networks such as Nym, Katzenpost, and the Lightning Network. Sphinx has two parts the payload that contains the content of the message and the headers that contains all the routing information from the client to the final destination.  While Sphinx has strong security and privacy properties such as integrity, wrap-resistence, unlinkability that protects against an adversary who tries to correlate input to output it does not protect against malicious clients who attempt to bias path selection because it is constructed centrally by clients.
  In this paper, we propose a decentralized variant of the Sphinx packet format that distributes header construction among multiple semi-honest third parties.
  We provide a formal analysis of the main security properties of the Sphinx packet format given various threat models. Additionally we implement our scheme in Python and evaluate the unlinkability property using the NIST SP 800-22 statistical test suite. Our empirical results suggest that our decentralized scheme achieves unlinkability, passing more statistical tests than the original Sphinx format.

\end{abstract}
