
\section{Introduction}

The Sphinx packet format, introduced by Danezis and Goldberg~\cite{sphinx} in 2009, has become a foundational component of modern anonymous communication systems.  
It is used in decentralized infrastructures such as the Lightning Network~\cite{poon2016bitcoin}, as well as mixnet-based systems including Nym~\cite{nym-network-whitepaper} and Katzenpost~\cite{infeld2025echomix}.

In these networks, messages traverse multiple hops, where each intermediary decrypts and forwards packets to the next entity in the path. 
The message content is protected through layered encryption in the Sphinx payload, and the routing information is similarly layered and encrypted within the Sphinx header. With this packet format, an adversary cannot correlate an input message with an output message based on packet structure or size. 
Additionally, an intermediary node along the message path does not learn its position within the route; it can infer only the immediately preceding and succeeding nodes, not the entire path. 
Sphinx achieves this through a compact packet structure that offers cryptographically robust unlinkability as well as per-hop integrity protection.

However, despite its strengths, the Sphinx packet format is fully constructed \emph{centrally} by the clients before entering the network which makes the system vulnerable to malicious clients. 
For example, a client may bias route selection to reduce the number of messages mixed at a given node in order to target a specefic client or reduce the overall anonymity provided by the system~\cite{benguirat2022mixnet}, or launch an (N-1)-attack~\cite{raymond2001traffic}.

In this work, we introduce \emph{DSphinx}, a \emph{decentralized Sphinx header construction} that distributes the computation across multiple independent semi-trusted third parties (STTPs).
To the best of our knowledge, this is the first work to decentralize the Sphinx packet format.
We argue that decentralizing the header construction is a necessary step toward achieving a more robust, verifiable, and flexible anonymous communication system.

Achieving decentralization while maintaining Sphinx's cryptographic guarantees raises several challenges.  
First, the protocol must prevent individual STTP, or any coalition of corrupted STTPs, from learning routing information or recovering cryptographic secrets.  
Second, mixnodes should learn no more than in the traditional Sphinx design.
Each hop must reveal only its own shared secret and the address of the next hop, but nothing about the rest of the route.  
Third, unlinkability must be preserved even against a powerful passive adversary capable of observing all traffic entering and leaving a mixnode and performing sophisticated cryptanalytic analysis. 
Finally, distributing the computation must not introduce any trapdoor, bias, or structural weakness that an adversary could exploit to correlate packets or manipulate header values.
Our construction meets these challenges by encoding routing information as elliptic curve points, splitting secrets via additive secret sharing, and using a homomorphic pseudorandom weighted checksum as an integrity mechanism that remains compatible with decentralized computation.

\noindent
In summary, our main contributions are as follows:
\begin{itemize}
    \item We design \emph{DSphinx}, the first \emph{decentralized Sphinx header construction}, enabling clients to distribute header computation while preserving the anonymity and cryptographic guarantees of the original Sphinx design;
    \item We provide a detailed security analysis of \emph{DSphinx},
considering passive and active network adversaries, corrupted mixnodes, and colluding STTPs;
    \item We provide a Python implementation of our header construction, which we will release under GPL license;
    \item Using the NIST SP-800-22 randomness test suite, we empirically demonstrate that the resulting \emph{DSphinx} headers are at least as indistinguishable from random bitstrings as centralized Sphinx, and in fact successfully pass slightly more randomness tests.
    \newline
\end{itemize}
